# components/bridge.md · Bridge（本地桥接 / 账号池）

> 覆盖：Bridge 运行状态、账号池、站点分组、登录二维码、额度异常、并发与换号
> 代码：`pages/doubao/index.tsx`、`components/canvas/canvas-doubao-accounts-panel.tsx`、`services/api/doubao-bridge.ts`、`doubao-bridge/*`
> 账号数据：`.doubao-accounts/<id>/`（`accounts.json` 记录能力级额度标记）

---

## 1. 概念边界

Bridge 是**跑在用户本机**的桥接服务：把画布上的生成请求转成本地浏览器里的真实操作。它不是一个"设置项"，它是**一个会挂掉的运行时依赖**。

因此视觉上必须随时能回答三个问题：

1. 桥接在跑吗？
2. 哪个账号在跑、可用吗？
3. 现在有几个任务在排？

## 2. 状态

| 状态 | 出现位置 | 表现 | 文案 |
|---|---|---|---|
| 未运行 | 任务条 / 账号池顶部 | 中性提示条 + "启动方法"入口，**不用红色错误样式** | 桥接未运行 |
| 运行中 · 空闲 | 账号池顶部 | 小绿点 + "已连接" | — |
| 运行中 · 忙 | 账号池 / 任务条 | 小黄点 + 运行数 `2/3` | 运行中 2 个 |
| 需登录 | 该账号行 | 账号行给"登录"按钮，按钮为 primary | 未登录 |
| 额度不足 | 该账号行 | 左侧 2px 红条 + 状态点红 + 文案标红 | 视频生成额度不足 |
| 站点不匹配 | 账号下拉 | 只列同站点账号；不匹配时不出现 | — |

规则：

- **未运行不是错误。** 用户没启动桥接是常态，用中性提示 + 引导，不要红屏报错。
- 额度异常必须**按能力**区分（生图额度 ≠ 视频额度），文案要写清是哪一种能力。
- 额度异常保留站点原文（悬停可见），不翻译、不改写。
- 该状态需跨重启保持（`accounts.json` 持久化），"刷新一下就好了"不是可接受的行为。

## 3. 账号池结构

```
账号池                          [刷新] [+]
─────────────────────────────────────
豆包
  ● 账号 138****1234      [当前]  ⋯
  ● 账号 139****5678    未登录   [登录]
  ▲ 账号 137****9012    视频额度不足
Dola
  ● 账号 dola-user-1              ⋯
─────────────────────────────────────
并发 2/3 · 桥接运行中
```

| 项 | 规定 |
|---|---|
| 分组 | 按站点分两组（豆包 / Dola），组标题 11px 大写感小字，不做分隔卡片 |
| 行高 | 40px（含两行信息时 48px），hover 给 `itemHover` |
| 站点标签 | 每个账号行一个小标签：豆包=雾霭紫，Dola=冰川蓝。**只用于标识站点，不用于状态** |
| 当前账号 | 左侧 2px 竖线 + 行文本 500 字重，不用整行填充底 |
| 操作 | 刷新、添加、删除、打开窗口、登录，收在行尾 `⋯`，删除为危险项 |
| 轮询 | 定时刷新不得改变当前选中、不得让列表闪烁（现有实现已按此修正） |

**刷新按钮只在手动刷新时旋转**。后台轮询不产生任何视觉反馈。

## 4. 登录流程

| 步 | 界面 |
|---|---|
| 1 | 点击"登录" → 弹出二维码面板（Popover 或小 Modal） |
| 2 | 二维码 + 一句提示（"用手机豆包 App 扫码" / "用手机 Dola App 扫码"） |
| 3 | 等待中：二维码下方显示状态点 + "等待扫码" |
| 4 | 成功：面板自动关闭，该行状态变已登录，**不弹成功 toast** |
| 5 | 失败/超时：面板内显示原因 + "刷新二维码" |

二维码是黑白位图，**不套品牌色、不加装饰边框**。站点不同必须用各自站点的二维码（豆包用 passport 接口，Dola 用其自身登录弹窗），不能互相替代。

## 5. 并发与换号

- 并发上限以配置为准（默认 3），界面上显示为 `运行中 2/3`。
- 超出上限的提交**立即失败并说明**"同时最多 3 个任务"，不做静默排队。
- 账号被标记额度不足时，任务按号池顺序顺延到下一个可用账号，**并在任务记录里显示换号原因**。
- 同一站点内才允许换号；跨站点（豆包任务换到 Dola 账号）必须报错 `ACCOUNT_PROVIDER_MISMATCH`。
- 换号是系统行为，界面只需在任务详情里说明，**不需要弹窗 interrupting 用户**。

---

## 6. 与画布的连接

- 账号池在画布左侧面板里是**紧凑版**：只显示状态点、账号尾号、异常标记。
- 完整管理在"豆包账号"页（`pages/doubao/`）。
- 两侧共享同一份选中账号状态，**不允许各自维护一份当前账号**（历史上导致面板互相刷新闪烁）。
- 画布上的模型下拉只列当前账号站点支持的模型；站点不匹配的组合不可选。

---

## 7. Do / Don't

**Do**

- 用中性提示表达"未运行"，用红色只表达"确实异常"。
- 把额度异常写成用户能懂的话：`视频生成额度不足`，悬停看原文。
- 账号行信息压到两行以内：尾号 + 状态。

**Don't**

- ❌ 把桥接未启动画成错误页。
- ❌ 用站点标签色表达状态（Dola 的青绿同时表示"正常"和"是 Dola"，会误读）。
- ❌ 给账号行加卡片、圆角、阴影（列表不是卡片流）。
- ❌ 轮询时闪烁或重置选中。
- ❌ 登录成功后弹 toast。
