# 离火设计体系

离火唯一的视觉与交互事实源。外部设计资源只在这里被**引用与转译**，不被搬运。

## 这份体系解决的问题

离火同时有两类界面，过去靠开发者各自"看着办"：

- **桌面工作区**（无限画布、节点、参数面板、生成流程）：高密度、暗色优先、极低视觉重量。
- **云端管理后台**（任务、模型、用户、管理员）：表格优先、明色优先、信息密度中等。

两者混用同一套间距与配色，就会既毁掉画布也不像后台。本体系用**一个色彩与字体内核 + 两套密度规则**解决，而不是两套设计语言。

## 读取顺序

| 你要做的事 | 按顺序读 |
|---|---|
| 开发任何新页面 | `DESIGN.md` → 对应 `components/*.md` |
| 只改按钮、输入框、弹层、表格 | `DESIGN.md` → `components/primitives.md` |
| 加动效、改过渡、做加载态 | `MOTION.md` |
| 调字号、行高、字重、中西混排 | `TYPOGRAPHY.md` |
| 用 Logo、定文案语气、做品牌露出 | `BRAND.md` |
| 找参考、翻案例 | `references/README.md` |

## 目录

```
design-system/
├─ DESIGN.md              视觉总纲：色彩、空间、层次、双轨规则
├─ MOTION.md              动效总纲：时长、缓动、编排、降级
├─ TYPOGRAPHY.md          字体与排版：字体栈、字阶、混排
├─ BRAND.md               品牌视觉：标志、双色哲学、文案语气
├─ references/            外部设计参考案例（只记录，不搬运）
└─ components/            11 个产品模块的组件规范
```

## 与代码的对应关系

本体系**不引入新变量**，一律对齐已有实现，避免出现第二套真相：

| 规范章节 | 代码事实源 |
|---|---|
| 色彩、圆角、antd 组件肤色 | `web/src/lib/app-theme.ts` |
| 画布背景、网格、选区、节点、工具栏 | `web/src/lib/canvas-theme.ts` |
| 页面级 CSS 变量、shadcn 令牌、品牌肌理 | `web/src/styles/globals.css` |
| 品牌名、标语、命名空间 | `web/src/constant/app.ts` |
| 标志 | `web/public/logo.svg` |

规范里出现的色值必须能在上述文件里找到出处。若规范需要新色（例如冰川蓝），会在 `DESIGN.md` 标注「已定规范 / 代码待落地」，不允许文档假装已生效。

## 三条硬规则

1. **外部参考只借判断，不借实现。** 任何外部页面都不允许被复制成离火的一屏，禁止整段照搬布局、文案与配色。
2. **一个资源只服务一个文件。** Jiro 只进 `references/03-jiro.md`，60fps 只进 `MOTION.md` 与 `references/04-60fps.md`，不得把五个资源混成一个"组件库"。
3. **不确定就写不确定。** 外部站点的付费墙内容、推断出的动效数值，必须原样标注，不许写成官方结论。
