# Jiro · 页面与区块设计参考

> 站点：https://jiro.build/

## 一句话定位

一个"AI 建站提示词库"：1464+ 个落地页模板与区块，浏览 → 复制提示词 → 粘进 Cursor / bolt.new / Lovable / v0 / Claude，由 AI 重建出同样的页面。

**它卖的是提示词，不是组件库；内容是营销落地页，不是产品界面。**

---

## 能学什么

1. **区块类型学**：一个完整落地页由哪些标准区块构成。这是它最可迁移的部分。
2. **区块的排序逻辑**：先讲价值、再给证据、最后给动作。
3. **行业分类法**：按行业归类模板，说明"同一区块在不同行业的形态差异"。
4. **提示词的写法**：把设计要求写成结构化的、AI 可执行的描述（与 `05-awesome-design-md.md` 的 9 节结构互相印证）。
5. **"所见即所得"的验收标准**：它承诺"粘进去得到一样的结果"，反过来说明好的设计说明必须具体到间距与层级。

## 不能学什么

1. ❌ **不能当产品 UI 组件库。** 它覆盖的是落地页（导航、定价、FAQ），离火的核心界面是画布与参数面板，**几乎没有交集**。
2. ❌ **不能抄它的提示词。** 提示词里包含完整的组件代码与实现指引，直接用等于把别人的实现搬进项目。
3. ❌ **不能用它生成的页面结构做官网。** 离火官网的品牌表达必须自研（见 `BRAND.md`）。
4. ❌ **不能依赖它的 MCP。** 其 MCP 需要 Jiro 账号授权，本项目未接入，也不应接入。
5. ❌ **不能把模板的配色/字体当成参考**——它们服务于各行业客户，与雾霭紫体系无关。

## 区块清单（可直接用于官网重建）

按 Jiro 的分类口径整理，离火官网若重做，按此顺序取舍：

| 区块 | 是否有必要 | 离火的做法 |
|---|---|---|
| 顶部导航 | 必要 | 极简 5 项：画布 / 生成 / 素材 / 文档 / 版本 |
| Hero（首屏） | 必要 | 标志 + 标语「以火为笔，炼万象」+ 一句定位 + 一个动作（进入画布） |
| 能力展示（feature grid） | 必要 | 三个：无限画布 / 模型直连 / 本地优先。**不用图标堆砌四宫格** |
| 工作流说明（how it works） | 可选 | 三步：拖入节点 → 选模型 → 生成。用真实截图而非插画 |
| 证据（social proof） | **不做** | 无客户背书时不做空壳 logo 墙 |
| 定价（pricing） | 不做 | 离火当前不涉及订阅 |
| 常见问题（FAQ） | 可选 | 只放 4 条：数据存哪 / API Key 安全 / 是否云同步 / 授权 |
| 页脚 | 必要 | 开源出处 + 授权 + 版本号 |

> 关键判断：**落地页区块清单可以借，区块的视觉与文案不能借。** 上表"离火的做法"一列即为转译结果。

## 提示词写法（可借鉴的元方法）

Jiro 的提示词之所以有效，是因为它把"设计"拆成了可执行项。离火在写 AI 生成指令时同样应包含：

1. 结构（有哪些区域、顺序如何）
2. 每个区域的层级关系（谁大谁小）
3. 具体数值范围（间距、圆角、字号）
4. 状态（默认 / hover / 空 / 加载 / 错误）
5. 明确禁止项

这正是 `DESIGN.md` 第 11 节"给 AI 的生成指南"存在的原因。
