# 60fps · UI 动效参考

> 站点：https://60fps.design/

## 一句话定位

真实 App 微交互录屏库：2140+ 条"delightful details"短片，覆盖 Revolut、Duolingo、CRED、Threads、Circle、Plasma、Runmo、Whatnot、X、App Store 等产品。

**它给的是"长什么样"，不给时长、缓动、代码。**

---

## 能学什么

1. **反馈的形状**：完成、失败、进行中分别用什么视觉语言表达（收束 / 收回 / 呼吸）。
2. **因果的可见性**：元素从哪来、落到哪去，用户能否一眼看懂。
3. **克制的尺度**：顶级产品的一次状态过渡通常极短、位移极小。
4. **连续性**：数值、进度、进度的填充是连续的，不跳格。
5. **"轻"的边界**：什么程度的动效算愉悦，什么程度开始变噪音。

## 不能学什么

1. ❌ **不能学时长的具体数字。** 站点不提供参数，任何数值都是反推，见下方说明。
2. ❌ **不能直接搬移动端手势**。60fps 绝大多数是触屏交互（长按、滑动、下拉刷新），离火是鼠标 + 键盘 + 画布。
3. ❌ **不能搬 Splash / 开屏动画**。移动 App 靠开屏动画建立仪式感，工具型 Web 产品开屏超过 800ms 就是缺点。
4. ❌ **不能搬装饰性弹跳、粒子、音效反馈**。
5. ❌ **不能把录屏当资产使用**（不可下载、不可嵌入）。

---

## 关于"反推数值"

本目录与 `MOTION.md` 中出现的时长，均为**目测反推**，方法：按 60fps 的命名前提（设计以 60 帧为基准）估算过渡跨越的帧数 × 16.7ms。

- 误差约 ±20%，**不是官方参数**。
- 只用作"量级校准"（是 100ms 级还是 300ms 级），不作为实现依据。
- 实现时的唯一依据是 `MOTION.md` 的时长表。

## 移动端 → 桌面画布的转译规则

60fps 的案例 95% 是移动端，直接照搬会出错。转译三条：

| 移动端模式 | 桌面画布的正确形态 |
|---|---|
| 长按弹出上下文菜单 | 右键菜单（120ms 淡入，指针右下 8px） |
| 底部抽屉上滑 | 侧边面板宽度过渡（180ms），不遮挡画布中心 |
| 全屏转场动画 | **不存在**。画布内的一切反馈都发生在节点局部，不做页面级转场 |
| 触觉/音效反馈 | 用描边、亮度、位置变化替代，不加音效 |
| 下拉刷新 | 顶部工具条的图标旋转（仅手动触发时），不整页下拉 |

## 使用建议

- 只在**写 `MOTION.md` 或实现某个具体交互**时打开，不要泛读。
- 一次只带走一个模式，写成一句可执行规则（如"删除用收回，不用消失"）。
- 判断标准：**这个动效是否让用户更清楚发生了什么？** 否则不做。
- 与本项目的关系仅限 `MOTION.md`。**不要**把 60fps 的内容写进 `components/`。
