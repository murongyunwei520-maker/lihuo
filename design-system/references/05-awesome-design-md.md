# awesome-design-md · AI 设计规范格式范本

> 仓库：https://github.com/VoltAgent/awesome-design-md（MIT）

## 一句话定位

一个 **DESIGN.md 合集**：把真实网站的设计语言拆成 9 节结构的纯文本规范，丢进项目根目录，AI 编码助手就能生成风格一致的 UI。

它源自 Google Stitch 提出的 DESIGN.md 概念，本质是"**给 AI 读的设计文档**"。

**它的价值是格式与颗粒度，不是任何具体数值。**

---

## 能学什么

1. **文档结构**：9 个固定章节，覆盖从气质到响应式的完整决策面。
2. **颗粒度标准**：每节都要落到可执行（色值 + 角色、字号 + 行高、组件状态、间距阶梯），而不是形容词。
3. **"给 AI 读"的写法**：短句、表格、显式禁止项、可复制的提示块。
4. **分工范式**：`AGENTS.md` 说"怎么建项目"，`DESIGN.md` 说"项目该长什么样"——离火已采用同一分工。
5. **Preview 的配套思路**：每个站点配 `preview.html` 与 `preview-dark.html` 双主题色卡，用于肉眼校验。

## 不能学什么

1. ❌ **不能搬 token。** 那些值的来源是"对公开站点的 CSS 逆向"，描述的是别人的品牌。
2. ❌ **不能把别人的设计语言写成我们的。** 尤其不要把 Linear 的紫、Vercel 的黑白直接认作离火的方向。
3. ❌ **不能整份复制 DESIGN.md 再改名字。** 这会产生一份"看起来完整但每条都不成立"的文档。
4. ❌ **不能依赖其 `preview.html` 作为离火规范的一部分**（那是别人站点的色卡）。
5. ❌ **不要引入其仓库文件到本项目**，只借鉴结构与写法。

## 9 节结构（离火已采用）

| # | 章节 | 离火对应实现 |
|---|---|---|
| 1 | 视觉主题与气质 | `DESIGN.md` §1（雾 / 火 / 纸） |
| 2 | 色彩与角色 | §2（雾霭紫 + 冰川蓝 + 语义色 + 双主题映射） |
| 3 | 字体规则 | `TYPOGRAPHY.md` |
| 4 | 组件风格 | `components/` 10 份 |
| 5 | 布局原则 | §3 空间与栅格（双密度表） |
| 6 | 层次与阴影 | §5 三级 elevation |
| 7 | Do / Don't | 各文档末节 |
| 8 | 响应式 | §9 |
| 9 | Agent 提示指南 | §11「给 AI 的生成指南」 |

**离火做的两处改造**（说明不是照搬）：

- 第 1 节用"意象 → 落点"的三词结构（雾/火/纸），而不是形容词堆叠。
- 第 5 节拆成**两套密度**（画布 vs 后台），因为离火有双轨界面——这是原仓库没有的问题。

## 高价值参照站点（只借分析维度）

以下条目的"设计语言"取自仓库 README 的公开描述，用于校准离火该往哪个方向走，**不引用其任何色值或字号**。

| 站点 | README 描述的设计语言 | 我们借什么 | 我们不借什么 |
|---|---|---|---|
| **Linear** | 极简、精确、紫色强调 | **最接近离火气质**：单色主导 + 一个强调色 + 极高精度对齐 | 其灰阶与紫值 |
| **Miro** | 无限画布美学、亮黄强调 | 无限画布的"界面后退"策略：画布本身几乎无装饰 | 黄色强调色 |
| **Raycast** | 深色 chrome、渐变点缀 | 暗色工具界面的层次处理（表面提亮 + 细描边） | 渐变点缀 |
| **Runway** | 电影感暗色 hero + 纸白阅读带 + 单一自有 sans | AI 创作工具的"作品优先"排版：让产出的画面占据视觉 | 其电影感暗调对比度 |
| **ElevenLabs** | 暗色电影感 UI、声波美学 | 生成类产品的"进行中"状态表达 | 声波图形语言 |
| **Figma** | 多彩但专业 | 复杂工具如何保持专业感（离火：靠克制，不靠多彩） | 多色系统 |
| **Vercel** | 黑白精度、Geist 字体 | 文档站的排版精度（`docs/` 可用） | 其字体（离火不引入字体） |
| **Notion** | 温暖极简、衬线标题 | 长文阅读区的舒适度 | 暖米色底（与雾霭紫冲突） |
| **Framer** | 大胆黑蓝、动效优先 | 动效与设计的耦合思路 | 高动效预算（离火相反） |

> 判断顺序：**Linear（气质）→ Miro（画布策略）→ Raycast（暗色层次）→ Runway（作品优先）**。其余作为对照，不作为方向。

## 使用建议

- 想改 `DESIGN.md` 的结构时，先对照这 9 节，确认没有丢决策面。
- 想写新规范时，检查是否满足"可执行"：每条能否直接换成一个类名或一个数值？
- 评估"我们的规范够不够"时，用它的 9 节做 checklist，而不是拿它的内容做模板。
